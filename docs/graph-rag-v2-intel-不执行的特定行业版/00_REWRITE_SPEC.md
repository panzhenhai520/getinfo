## 二、⚠️ 最重要的架构原则：两层彻底分离（2026-10-08 修正，优先级高于下面所有对照）

**不要把"医疗词"替换成"我们自己的行业词"。** 那只是把别人的领域耦合换成我们的领域耦合，
等于没改。正确做法是**把领域词中性化，行业只作为配置进入**：

| 层 | 内容 | 硬规则 |
|---|---|---|
| **通用引擎层**（所有 Phase 的算法、契约、图结构） | 检索编队、Verifier、Evidence Graph、Gap Analyzer、Context Planner、Memory Graph、Answer Composer | **行业无关**。只允许出现抽象类型：`Entity` / `Claim` / `Evidence` / `Source` / `Scope` / `TimeWindow` / `Relation` / `Verifier` / `Gap`。**不得出现任何具体行业词**——既不许有"药品/适应症/病历"，也不许有"私募基金/工控安全/家族信托" |
| **行业配置层**（每个行业包各自提供，不改引擎） | 关键词与锚点表、信源清单与权威级别、关系类型定义、时效策略、实体词表、分类权重 | **只以配置与数据进入**；算法不得依赖任何具体行业 |

**行业只允许出现在三个地方，且都是"作用域 / 配置"**：
1. **准入闸门**——判断某条内容是否属于本作用域的合格证据（这是关键词表，配置项）；
2. **作用域隔离**——证据与记忆必须按 `scope` 收口。契约里统一用中性的 **`scope`（作用域/租户键）**，
   并注明"**当前实现 = `industry_pack_id`**"；换成任何其它维度（客户、部门、项目）都成立，
   算法不得假设它一定是行业；
3. **策略差异**——权威级别、时效长短、关系类型因包而异，一律写在包的配置里。

**因此 Phase 01 的契约必须包含一个"作用域配置接口"**：规定一个配置单元需要提供什么
（关键词/锚点、信源与权威级别、关系类型、时效策略、实体词表），而不是把某个行业的词写死。

> 下面第二节的对照表**只用于消除他方项目残留**（患者/EMR/临床/就诊/处方等一律中性化），
> **不得**反向把我们的行业词写进引擎层。

## 二之一、术语对照表（医疗 → 中性概念，逐条替换）


| 医疗原文概念 | 改写为本系统的 | 说明 |
|---|---|---|
| 患者 / patient | **用户**（分析师/运营），必要时细分"提问用户" | 对话主体 |
| 医生 / clinician | **分析师**或**助手**，按上下文二选一 | 判读者 |
| 就诊 / encounter | **一次问答 run**（`qa_runs` 里的一个 run） | 会话边界 |
| 会话 / session | **会话**（同一用户连续对话），跨会话 = **跨 run / 跨会话** | 记忆边界 |
| EMR / 电子病历 | **内部结构化数据集**（证据池表 **`articles`** + `article_intel_classifications` + `intel_article_events` + `intel_subject_canonical`） | 内部数据源 |
| 病历细节 / 患者事实 | **情报事实**（文章、公告、研报、监管文件里的事实） | 证据内容 |
| 临床指南 / guideline | **权威来源**（"权威"由**作用域配置的 `authority_level`** 判定；引擎不内置任何具体来源类型） | 权威证据 |
| 诊断 / diagnosis | **评估 / 结论**（中性，不写具体业务类别） | 结论层 |
| 用药建议 / treatment | **行动建议 / 决策参考** | 输出层 |
| 患者追问 / ASK_PATIENT | **向用户澄清 / ASK_USER** | 动作类型 |
| 医疗 Memory scope | **记忆作用域**：`owner_user_id` + `scope` + 会话 三层隔离（当前实现 = `industry_pack_id`） | 越权即事故 |
| Clinical Memory Safety（Phase 15） | **记忆安全与作用域隔离**（Phase 15 改名；内容：不得跨 `scope`、跨用户泄露；来源合规；可撤销可审计） | 安全底线 |
| 医院/科室 | **行业包 / 子主题** | 组织维度 |
| SAGE-RAG 统一采集（KB/EMR/DB/Web/Ask Patient） | **统一情报采集**：证据池(KB) / 内部结构化数据(DB) / 公网(WEB) / 向用户澄清(ASK_USER) / 趋势与热榜(TREND) | Phase 14 |
| 临床指南时效 VERY_SHORT | **政策/监管原文时效短**（发文即最高价值，几天后只作背景） | Freshness 示例 |
| 患者当前状态 SESSION/ENCOUNTER_BOUND | **用户本次会话的关注点 / 当前 run 的约束（行业包、时间窗、股票标的）** | 时效示例 |
| 临床安全 / 用药安全 | **结论安全**：不得给出无证据支撑的**高影响结论**（哪些类别属于"高影响"由**作用域配置声明**）；引用必须可回溯 | 安全 |
| 隐私 / HIPAA 类合规 | **作用域隔离与来源合规**（不得跨 `scope` 取证据；来源许可证闸门，见下） | 合规 |
